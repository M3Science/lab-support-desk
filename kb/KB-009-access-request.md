# KB-009: Requesting new user access or a security role

| Applies to | Typical priority | First owner | Escalate to |
|---|---|---|---|
| New hires, role changes | P4 (P3 if the user is scheduled on a bench today) | Tier 1 intake, Tier 2 builds | Tier 2 |

## Symptoms
- A new user cannot log in.
- An existing user is missing a function they need.

## Before you start
- Access requires manager approval and completed training. Do not grant access without both.

## Steps
1. Collect the user's name, department, role, and start date.
2. Attach manager approval and the training record.
3. Route to Tier 2 to create the account or assign the role that matches the job, and nothing broader.
4. Confirm with the user that they can reach the needed functions.

## Escalate when
- Always routes to Tier 2 for the build step.

## Close the ticket with
User, role granted, approval reference, access confirmed Y/N.
